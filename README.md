# 통합 대시보드 (한투 자산관리 + 보험 고객관리)

기존 두 대시보드를 하나로 합친 단일 앱입니다.

- **한투(kis-dashboard)**: 자산 엑셀 분석 · 고객·자산 CRM · 영업 도출 · 은퇴 시뮬 · E2EE 동기화
- **보험(toss-reports)**: 분기 연락 스케줄 · 생일 관리 · 연락 이력 · 보험 리포트 배포

고객은 **채널 태그(한투 / 보험 / 양쪽)** 로 한 곳에서 통합 관리합니다.

## 구성

- `index.html` — 단일 페이지 앱 전체
- `lib/` — Pretendard 폰트 · Chart.js · SheetJS(xlsx) · html2canvas (모두 로컬 번들)
- `.nojekyll` — Jekyll 비활성 (정적 그대로 서빙)
- `.gitignore` — 고객 데이터/백업 JSON 커밋 금지

## 데이터 저장 (중요)

- **고객·자산·보험 데이터는 이 저장소에 커밋되지 않습니다.** 브라우저(IndexedDB)에 저장되고, 동기화를 켜면 **별도 비공개 저장소에 AES-GCM으로 암호화**되어 올라갑니다.
- 따라서 이 저장소는 **공개로 둬도 개인정보가 노출되지 않습니다**(소스 코드만 있음).
- 보험 리포트(HTML)와 공유 링크는 기존처럼 **toss-reports** 저장소에 배포됩니다.

> ### ⚠ 동기화 암호를 반드시 설정하세요
>
> **동기화 암호를 정하지 않으면 실제로는 암호화되지 않은 것과 같습니다.**
> 암호가 없을 때 쓰이는 기본 키는 `'khs-wm-e2ee::' + 저장소이름` 이라, 저장소 이름을
> 아는 사람이면 누구나 똑같이 만들어 냅니다. 무작위 salt와 PBKDF2 20만 회는 *모르는*
> 암호를 추측하기 어렵게 할 뿐, 알려진 문자열 앞에서는 아무 일도 하지 않습니다.
>
> 즉 이 상태에서는 **데이터 저장소를 읽을 수 있는 쪽(GitHub 포함)이 내용을 볼 수 있습니다.**
> `설정 · 백업 → 동기화`에서 암호를 정하면 경고가 뜨고, **다음 동기화 때 그 암호로 다시
> 암호화되어** 올라갑니다. 그때부터 GitHub도 내용을 못 봅니다.
>
> 기존 데이터는 기본 키로도 계속 열리므로(복호화 후보에 남겨 둠) **암호를 새로 정해도
> 데이터를 잃지 않습니다.** 다만 다른 기기에서는 그 암호를 한 번 입력해야 합니다.

### 자격증명 보관

동기화 암호와 데이터 repo 토큰은 **암호화해서** 보관합니다(`ab_vault`).
금고 키는 IndexedDB에 있는 **추출 불가(non-extractable) AES-GCM 키**라 원시 바이트를
꺼낼 수 없습니다 — `exportKey`도 실패합니다. 예전처럼 localStorage를 열어 보는 것만으로는
아무것도 얻을 수 없습니다.

- 설정 화면은 저장된 비밀값을 **다시 화면에 채워 넣지 않습니다**(어깨너머·화면공유·스크린샷).
- `전체 삭제`는 금고까지 함께 비웁니다.
- PIN이 아니라 IndexedDB 키로 봉인하는 이유: 이 앱에는 생체인증 잠금해제가 있고
  (WebAuthn 검증만 할 뿐 키 재료를 주지 않습니다) 해제 직후 자동 동기화가 돕니다.
  PIN으로 봉인하면 생체인증 사용자는 동기화 때마다 PIN을 다시 눌러야 합니다.

> ⚠ 이 구조도 **XSS는 막지 못합니다.** 페이지에서 스크립트가 실행되면 그 키로 금고를
> 열 수 있습니다. 브라우저 프로파일을 통째로 복사당하는 경우도 마찬가지입니다.
> 막아 주는 것은 *저장소를 읽는 것만으로 비밀값이 새는* 경로입니다.

## 배포 방법 (GitHub Pages)

저장소 이름: **KHS-WM** · 접속 주소: **https://hyunseoung-ko.github.io/KHS-WM/**

1. GitHub에서 새 저장소 `KHS-WM` 생성 (빈 저장소, README 추가 안 함).
2. 이 폴더에서 푸시 (git remote는 이미 설정됨):
   ```
   git push -u origin main
   ```
3. 저장소 **Settings → Pages → Source: main / (root)** 로 설정.
4. 접속: `https://hyunseoung-ko.github.io/KHS-WM/`

## 최초 설정 (앱 안에서)

1. **PIN 6자리** 생성 (첫 실행 시).
2. **설정 · 백업 → 동기화**: 데이터 repo(`<계정>/kis-dashboard-data`) · 토큰 · 동기화 암호 입력 → 기존 한투 데이터가 그대로 복원됩니다.
3. **설정 · 백업 → 📥 보험 고객 가져오기**: toss-reports 토큰으로 기존 보험 고객 172명을 통합 CRM으로 1회 이전 (이름 기준 한투 고객과 자동 병합).
4. **리포트 탭 → 토큰 연결**: 같은 toss-reports 토큰으로 연결하면 리포트 배포·관리 가능.

> 토큰은 2가지입니다: ① E2EE 동기화용(데이터 repo) ② toss-reports용(보험 가져오기+리포트). 하나의 fine-grained PAT에 두 repo 권한을 함께 주면 한 개로도 됩니다.

### toss-reports 토큰 보관 방식

토큰은 이 기기에 **90일간** 보관됩니다(GitHub fine-grained PAT의 권장 유효기간).
그때쯤이면 토큰이 GitHub 쪽에서도 만료되므로, 더 짧게 잡아 봐야 재입력만 늘어납니다.

공용 PC에서 쓸 일이 있으면 **토스 대시보드 → GitHub 토큰 관리**에서 `기억`을 끄면
브라우저를 닫을 때 사라집니다. 두 앱이 같은 저장소를 보므로 그 선택이 이 앱에도 그대로
적용됩니다.

토큰이 만료되었거나 폐기되어 GitHub가 `401`을 돌려주면 **즉시 지웁니다**. `403`(권한 부족)은
토큰 자체는 멀쩡한 상태이므로 지우지 않습니다 — 저장소 범위와 Contents 권한을 확인하세요.

> GitHub Pages 프로젝트 사이트는 **경로만 다르고 오리진이 같습니다**
> (`hyunseoung-ko.github.io/KHS-WM` · `/toss-reports`). 브라우저 저장소는 오리진 단위라
> 두 앱이 같은 토큰을 공유합니다 — 한쪽에서 넣으면 다른 쪽도 바로 연결됩니다.
> 그래서 보관 로직은 **양쪽이 형식까지 똑같아야** 합니다: 이 앱은 `index.html` 상단
> `GitHub 토큰 보관` 블록에, toss-reports는 `lib/gh-auth.js`에 같은 구현을 둡니다.
> **한쪽 형식을 바꾸면 반드시 양쪽을 함께 바꿔야 합니다.**
>
> ⚠ 이 방식은 토큰이 브라우저에 **노출되는 시간**을 줄일 뿐, 페이지에서 스크립트가
> 실행되는 상황(XSS)까지 막지는 못합니다. 백엔드 없는 정적 페이지에서는 토큰이
> 브라우저 안에 있을 수밖에 없기 때문입니다.
